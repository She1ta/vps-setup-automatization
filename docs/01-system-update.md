# Этап 01 — обновление системы VPS

Этот модуль отделён от существующего `simple_setup.sh` и **не меняет SSH, firewall, VPN, Docker, репозитории и версию ОС**. Исходный скрипт оставлен без изменений.

## Назначение

- Определить Debian/Ubuntu, архитектуру и запущенное ядро.
- Проверить состояние dpkg и доступное пространство.
- Выполнить `apt-get update`, `upgrade`.
- Выбрать подходящий официальный метапакет ядра (Debian, Ubuntu и основные облачные разновидности); в контейнерах пропустить обновление ядра хоста.
- Повторить обновление индексов и выполнить `full-upgrade` с предварительной проверкой удалений.
- Выполнить контролируемый `autoremove --purge` и `autoclean`.
- Показать незавершённые обновления, закреплённые пакеты, DKMS и признак необходимости перезагрузки.
- Сохранить журнал в `/var/log/vps-setup`.

## Запуск

Сначала создайте snapshot VPS средствами хостинг-провайдера и убедитесь, что доступна веб-консоль восстановления.

```bash
# Просмотреть действия, которые APT планирует выполнить, не меняя систему.
bash scripts/01-system-update.sh --dry-run

# Запустить реальное обновление пакетов и поддерживаемого ядра.
sudo bash scripts/01-system-update.sh

# На VPS, где ядро управляется провайдером, обновить только пользовательские пакеты.
sudo bash scripts/01-system-update.sh --skip-kernel

# Явно выбрать проверенный метапакет ядра (название зависит от ОС).
sudo bash scripts/01-system-update.sh --kernel-package linux-image-cloud-amd64
```

## Ограничения и безопасность

1. Автоматическая перезагрузка **отключена**. После установки ядра сначала проверьте `dkms status`, состояние `/boot` и конфигурацию загрузчика.
2. `full-upgrade` прекращается, если требуется удаление пакетов, пока не указан `--allow-removals`.
3. `autoremove` по умолчанию не удаляет старые ядра. Используйте `--allow-kernel-autoremove` только после успешной загрузки нового ядра и проверки резервного варианта.
4. Поддержка специфических ядер провайдера, загрузчиков и нестандартных Ubuntu HWE/OEM метапакетов не гарантирована: используйте `--skip-kernel` либо проверенный `--kernel-package`.
5. `--dry-run` использует текущие локальные индексы APT: эта симуляция не заменяет тест на реальном VPS.
6. Скрипт не выполняет обновление дистрибутива (например, Ubuntu 22.04 → 24.04); это отдельная процедура с резервной копией и планом отката.
7. Скрипт использует исключительно официальные настройки APT сервера и **не скачивает и не запускает сторонние установочные shell-скрипты**.
8. Даже если проверка удаления пройдена, изменения в сторонних репозиториях между симуляцией и исполнением требуют внимания администратора.
9. Автоматическое обновление конфигурационных файлов минимизировано, но пакетные post-install-скрипты по-прежнему могут менять сервисы.

## Что протестировано

- Проверка синтаксиса: `bash -n scripts/01-system-update.sh`.
- Вывод `--help`.
- Dry-run Debian-контейнера: завершён успешно; обновление ядра хоста правильно пропущено.
- Неизвестный аргумент: возвращается код 2.

**Не проверено:** фактическое обновление пакетов/ядра на отдельной KVM VPS с Debian и Ubuntu. До такого теста нельзя считать сценарий производственно аттестованным.
